# CubePath managed databases

CubePath operates the whole instance: high availability, automatic failover, backups and a public connection endpoint.

## Read

- `cubepath_mdb_list` lists the instances with engine, version, status, replicas, and the host and port to connect to. With `md_uuid` it adds plan, location, backup policy, protection, and the logical databases and users.
- The admin password is only in the CubePath dashboard. This channel never returns passwords or connection strings that contain one.

## Create an instance

1. `cubepath_mdb_plan_list` narrowed with `engine` and `location`. Prices are USD per hour PER NODE: the monthly cost is the hourly price x replicas x 730.
2. Confirm engine, version, plan, number of replicas and the monthly estimate. There are no major version upgrades later, so pick the version carefully.
3. `cubepath_mdb_create` with `project_id`, `name`, `engine`, `version`, `plan_uuid` and `replicas` (and, if the user wants, `backup_schedule_cron` and `backup_retention_days`).
4. `cubepath_wait_for_status` with `resource_type` `managed_database`. It takes several minutes: if the wait times out, call it again; never create the instance twice.

## Give an application access

1. `cubepath_mdb_object_create` with `object_type: database` and its `name` (Valkey has no logical databases).
2. `cubepath_mdb_object_create` with `object_type: user`, `name` and a `password` the user chooses. Ask for it: a password generated by the server would never be shown, and the user would be unusable.
3. Give the user the host and port from `cubepath_mdb_list`, plus the database and user names.

Suggest a dedicated user per application instead of sharing the admin account.

## Performance and tuning

- `cubepath_mdb_inspect` with `view: metrics`: connections, CPU, memory and replication lag over a time window. Use it to decide whether to scale.
- Engine parameters: read `cubepath_mdb_inspect` with `view: config` FIRST (valid parameters, ranges, and which ones restart the instance), then `cubepath_mdb_reconfigure` with `params`.
- `cubepath_mdb_reconfigure` takes EXACTLY ONE of `replicas` (more or fewer nodes), `plan_uuid` (bigger or smaller plan, same location and engine) or `params`. More replicas or a bigger plan raise the bill: confirm first. Follow it with `cubepath_wait_for_status`.
- Name, label, backup policy and delete protection: `cubepath_mdb_update`. Suggest protection for production databases.

Backups run on the instance's backup policy. There is no tool to take or restore a backup on demand; for that, send the user to the CubePath dashboard or support.

## Delete

- `cubepath_mdb_object_delete` removes one logical database with ALL its data, or one user, who can no longer connect. Confirm first.
- `cubepath_mdb_delete` destroys the instance with all its data, databases, users and backups. It cannot be undone: ask whether the user has an export and get an explicit yes. A protected instance is refused; turn protection off with `cubepath_mdb_update` only if the user asks.
